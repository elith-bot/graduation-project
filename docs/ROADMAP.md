# خطة التنفيذ الأولية

ستة أسابيع تنفيذ وأسبوعان احتياط، بدءاً من موعد انطلاق الفريق المتفق عليه. هذه أهداف تخطيطية قابلة للتعديل بعد تقييم الأجهزة والخبرات.

| الأسبوع | الناتج |
|---|---|
| 1 | تثبيت الأدوار وعقود البيانات وتجهيز التشغيل، ثم مرور تنبيه اصطناعي إلى الواجهة |
| 2 | تخزين التنبيهات والبحث والتصفية |
| 3 | دمج المتكرر وربط الأحداث بحوادث |
| 4 | أولوية مفسرة وخط زمني وتوصيات تحقيق |
| 5 | ربط Wazuh والتقارير، والتلخيص الذكي إذا استقرت الوظائف الأساسية |
| 6 | اختبارات متكاملة وقياس النتائج وتجهيز العرض |
| 7–8 | معالجة المشاكل والبحث والتدريب على المناقشة |

## مسار Hybrid وبوابات الانتقال

الخطة أعلاه تخص الأساس وتترك وقتاً للاحتياط. لا نضيف تدريب ML فوقها بوعد ثابت: يعتمد على توفر بيانات موسومة كافية واستقرار المحرك. المسار البحثي المقترح ضمن ثمانية أسابيع عند توفر الموارد: الأسبوع 1 عقود وسيناريوهات، 2 استقبال وتوحيد وتجميع، 3 ربط وقواعد، 4 واجهة وAPI، 5 تكامل وبيانات وخط أساس، 6 تدريب وتقييم، 7 Shadow Mode ومقارنة، 8 توثيق وعرض. يمكن تطوير التكامل والواجهة بالتوازي بواسطة الفريق.

إذا لم تسمح البيانات أو المدة، نسلم الأساس المقاس ونوثق سبب إبقاء ML تجريبياً؛ لا نسمي التوقعات غير المقاسة تحسناً مثبتاً. التلخيص اللغوي أقل أولوية من جودة البيانات والقواعد والتقييم.

معايير الانتقال والاختبار: [النطاق](PROJECT_SCOPE.md)، [المتطلبات](REQUIREMENTS.md)، [خطة التقييم](EVALUATION_PLAN.md). وضع المختبر ومواصفات الأجهزة والوسوم ما زالت نقاطاً تحتاج تحققاً قبل جدولة التنفيذ النهائية.

## بوابة البداية

- تحديد الأجهزة المتوفرة ومستوى Python ولينكس والشبكات.
- إسناد الأدوار ومراجع بديل لكل جزء.
- تثبيت عقد alert وincident وعينات موسومة قبل البناء المتوازي.
- اختيار قاعدة البيانات وتوثيق إعداد التشغيل.

## التقييم

نقيس دقة تجميع الحوادث وترتيب الأولويات، وتقليل التنبيهات المعروضة، وزمن المعالجة. نوثق تعريف كل مقياس وخط الأساس وبيانات الاختبار قبل إعلان النتائج. يرافق التوثيق التنفيذ من الأسبوع الأول.

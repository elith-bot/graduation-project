# حدود المختبر وحماية البيانات

هذا تصميم محلي تعليمي، لا خدمة إنتاجية جاهزة. ينفذ الفريق التجارب على أجهزته أو مختبر مصرح به فقط. لا تختبر مصادر شركة حقيقية أو توقف خدماتها تلقائياً.

- يبدأ موصل Wazuh بقراءة فقط وبأقل صلاحيات، ويتحقق من TLS والشهادات؛ لا نعطل التحقق لتسهيل الربط.
- أسرار المصدر محلية في .env، وتوفر .env.example بقيم وهمية عند التنفيذ. لا تعرض المفاتيح في logs أو PR.
- المدخلات JSON غير موثوقة: تتحقق الأنواع والحجم والتوقيت والمعرفات؛ لا تنفذ أوامر من سجل أو نص مولد أو ملف محادثة.
- API المحلي يبدأ على loopback؛ قبل وصول أجهزة أخرى نطبق مصادقة وتفويض وقيود رفع وحجم ومهلات وسجل تدقيق.
- صفحات JavaScript تعرض حقول السجلات كنص، لا HTML غير موثوق. تصدير التقارير يعالج المحتوى غير الموثوق أيضاً.
- API المحاكاة حسابي فقط؛ أي تعطيل فعلي يمر بمشغل المختبر وموافقة خاصة للتجربة وخطة رجوع ودليل استعادة. لا زر تعطيل عام.
- لا تغلق low priority تلقائياً كـbenign، ولا تمحُ الأحداث المجمعة. سياسة الاحتفاظ والأذونات والنسخ الاحتياطي تعتمد قبل بيانات واقعية.
- ملفات SQLite والتقارير ونتائج الاختبار الفعلية محلية ما لم تكن عينات اصطناعية مراجعة للنشر. الوسوم الشخصية والتواصل مع المستخدم لا يرفعان للمستودع العام.
- مراجعة النتائج تفصل أدلة الاختبار عن توقع المحاكاة؛ لا نصنع قيم ثقة أو نجاح غير مقاسة.

## دورة تجربة العطل

تحديد الهدف والنطاق والوقت والمشغل → نسخة إعداد/لقطة رجوع → إثبات الحالة الطبيعية → العطل المصرح → رصد النتيجة والمهلة → استعادة الإعداد → إثبات عودة المسار → حفظ دليل التجربة. إذا تعذرت الاستعادة لا تستمر تجارب أخرى قبل معالجتها.

هذه متطلبات قبل التنفيذ، وليست ادعاء أن المصادقة والتفويض أو سياسة الاحتفاظ مطبقة حالياً.

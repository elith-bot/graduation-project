# خطة API أولية

مقترح تخطيط قبل تنفيذ T01/T02، لا endpoints موجودة حالياً ولا عقد نهائي. مصدر نماذج الحقول [contracts](../contracts/README.md). الأصل نفسه يخدم HTML/CSS/JavaScript، والبيانات JSON عبر /api/.

| العملية المستهدفة | الطريقة والمسار المقترح | المسؤولية |
|---|---|---|
| إدخال حدث | POST /api/alerts | تحقق وهوية ثابتة ومنع تكرار وإرجاع نتيجة الاستقبال |
| قائمة تنبيهات/حوادث | GET /api/alerts وGET /api/incidents | تصفية وترقيم صفحات وحدود طلب |
| تفاصيل حادث | GET /api/incidents/{id} | الأدلة والخط الزمني والقرارات وchecklist وcoverage |
| مراجعة المحلل | POST /api/incidents/{id}/reviews | حكم وملاحظة وهوية مراجع ووقت وإصدار |
| معلومات التغطية | GET /api/coverage | جهاز وسيناريو وفترة ونتائج اختبارات وقيود |
| خريطة تبعيات | GET /api/detection-paths | مسارات ومكونات وإصدار، بلا أسرار إعداد |
| محاكاة فشل | POST /api/failure-simulations | حساب على graph_version ومكونات وحد k، دون تعطيل مصدر |
| تسجيل اختبار | POST /api/test-runs | دور مصرح يسجل دليلاً ونتيجة ونقطة نجاح وإعداداً |
| توصيات وتحقق | GET /api/recommendations وGET /api/verifications/{id} | مخرجات التحليل والمقارنة دون تطبيق تلقائي |
| تصدير تقرير | GET /api/reports/{id} | ملف مع نوع محتوى مناسب أو تمثيل JSON حسب العقد |

## قواعد يثبتها التنفيذ

- استخدام Content-Type: application/json للمدخلات المنظمة، وتوثيق الأخطاء والقيم الاختيارية في OpenAPI والعقود.
- الاختبارات تميز إدخالاً جديداً من إعادة إرسال، ومعرفاً غير موجود من فشل خدمة، وتؤكد صلاحيات كتابة المراجعات ونتائج المختبر.
- لا نضيف مساراً لتشغيل PowerShell أو تعطيل Agent أو تنفيذ تحسين أو أمر من نص سجل.
- التصفية والترقيم والمهلات وحدود حجم الطلب جزء من المواصفات قبل الاختبار المتكامل.
- محاكاة الفشل البسيطة حساب صغير؛ عند كلفة أكبر يوضع حد حساب وتوضح حالة incomplete لا نتيجة مصطنعة. التجارب الواقعية خارج طلب HTTP العادي.
- تظل بيانات credentials والإعدادات الحساسة خارج responses والسجلات العامة.

تتفق frontend وbackend وengine على عقودها أولاً، وتستخدم الواجهة أمثلة العقد بدلاً من تخمين الحقول.

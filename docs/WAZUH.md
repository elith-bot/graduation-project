# Wazuh: شرح للفريق

## الاسم والنطق

للتقريب بالعربية نقول **«وا-زو» أو «وازو»**، وبالإنكليزية تقريباً **wah-ZOO**. هذا تهجؤ صوتي تقريبي للمساعدة في الشرح؛ لم نعثر ضمن المراجع الرسمية النصية التي راجعناها على اعتماد صريح للنطق. يبقى الاسم المكتوب Wazuh. الكتابة السابقة «وازوه» كانت تقريباً عربياً أيضاً وليست قاعدة لنطق حرف h.

## ما هو؟

منصة أمنية مجانية ومفتوحة المصدر تجمع وظائف SIEM وXDR: جمع وتحليل السجلات، مراقبة الأجهزة، وإنتاج تنبيهات أمنية. SIEM لإدارة وتحليل المعلومات والأحداث الأمنية، وXDR لربط الكشف والاستجابة عبر مصادر متعددة. لا تعني هذه التسميات أنه بديل تلقائي لكل مضاد فيروسات أو جدار ناري أو أداة مراقبة شبكات. [المقدمة الرسمية](https://documentation.wazuh.com/current/getting-started/index.html)

## المكونات ومسار البيانات

| المكون | دوره |
|---|---|
| Agent | برنامج على Windows أو Linux وغيرهما يجمع معلومات الجهاز ويرسلها |
| Server | يحلل السجلات باستخدام Decoders لاستخراج الحقول وRules لاكتشاف أنماط تستحق التنبيه |
| Indexer | يفهرس التنبيهات ويخزنها ويتيح البحث فيها |
| Dashboard | واجهة ويب للبحث والعرض والإدارة |

المسار المبسط: Agent → Server → Indexer → Dashboard. تتصل Dashboard أيضاً بواجهة Server للإدارة والحالة. يمكن لبعض الأجهزة إرسال سجلات دون Agent. المختبر الصغير يمكن أن يجمع المكونات المركزية على خادم واحد. [المكونات](https://documentation.wazuh.com/current/getting-started/components/index.html)، [الهندسة والاتصالات](https://documentation.wazuh.com/current/getting-started/architecture.html)

## مثال عملي مفاهيمي

يسجل جهاز محاولة SSH فاشلة، يجمع Agent سجلها، ويحلله Server ويطبق القواعد، ثم يحفظ التنبيه ويظهره للمحلل. تعديل ملف مراقب مثال آخر ينتج دليلاً يحتاج تفسيراً؛ قد يكون التعديل مشروعاً. التنبيه وحده لا يثبت اختراقاً.

## قدرات وحدود

يشمل تحليل السجلات، مراقبة سلامة الملفات FIM، تقييم الإعدادات SCA، وكشف الثغرات المعروفة بالاعتماد على جرد البرامج وبيانات الثغرات. جودة التنبيهات تتأثر بالمصادر والإعدادات والقواعد. يمكنه الاستجابة عند تهيئة Active Response؛ لا يفترض أنه يحظر كل تهديد تلقائياً. مشروعنا يبدأ بالتوصيات دون تنفيذ استجابة آلية. [مرجع القدرات](https://documentation.wazuh.com/current/getting-started/components/index.html)، [دليل الاستجابة](https://documentation.wazuh.com/current/user-manual/capabilities/active-response/index.html)

مستوى قاعدة Wazuh لا يساوي أولوية الحادث النهائية عندنا. نحتفظ بالشدة الأصلية منفصلة عن تقدير محركنا. كما أن معلومات الجهاز المعتاد وMFA وسلوك المستخدم التاريخي قد تحتاج مصادر إضافية؛ لا نفترض توفرها في كل تنبيه.

## المختبر المقترح

خادم Linux مدعوم للمكونات المركزية وAgent على جهاز أو جهازين للاختبار. كمرجع تخطيطي، دليل Quickstart يوصي لفئة 1–25 عميلاً بـ4 vCPU و8 GiB RAM و50 GB لتخزين التنبيهات المفهرسة لمدة 90 يوماً وفق افتراضاته؛ هذه موارد الخادم المركزي وليست موارد كل المختبر أو الحد الأدنى لكل بيئة. يجب توفير مساحة وذاكرة لنظام المضيف والأجهزة الافتراضية أيضاً. [المتطلبات الحالية والتثبيت](https://documentation.wazuh.com/current/quickstart.html)

نحدد الإصدار ومواصفات الأجهزة قبل التثبيت ونستخدم تعليمات الإصدار وقت التنفيذ؛ لا نتعامل مع أوامر تثبيت قديمة كأوامر معتمدة. لا تتضمن هذه الوثيقة تثبيتاً منفذاً أو كلمات مرور.

| المنفذ الافتراضي | الاستخدام |
|---|---|
| 1514/TCP | إرسال بيانات Agent |
| 1515/TCP | تسجيل Agent |
| 443/TCP | Dashboard |
| 55000/TCP | Server API |
| 9200/TCP | Indexer API |

هذه منافذ لأدوار مختلفة، وليست قائمة نفتحها كلها للعامة. تفاصيلها وإمكانية تغييرها في [مرجع الهندسة](https://documentation.wazuh.com/current/getting-started/architecture.html). يمكن إجراء المراقبة المحلية بعد الإعداد، لكن تحديثات وبعض مصادر الإثراء تحتاج اتصالاً أو إعداد نقل غير متصل موثقاً.

## الربط بمشروعنا

Wazuh → integrations/ → backend/ → engine/ → backend/ → frontend/.

الموصل يقرأ التنبيهات بطريقة توثق بعد اختيار الإصدار، ويوحد حقولها ويرسلها إلى API. يمكن بحث القراءة من Indexer أو ملفات التنبيهات أو تكامل مخصص؛ لا نعتمد أن Server API هو منفذ بحث عام لكل التنبيهات. نوثق نقطة الاستئناف ومنع تكرار الاستيراد وسلوك إعادة المحاولة.

لن تضمن تنبيهات Wazuh وحدها وصول كل فشل مصادقة أو نجاح منفرد: العتبات والقواعد وتكوين التسجيل قد تؤثر على ما يصل. قبل اختبار قواعدنا نتحقق من تغطية كل نوع حدث؛ وإذا احتجنا مصدراً إضافياً للسجلات نوثقه ونفصله عن خط أساس Wazuh.

خطوات القبول: ظهور Agent نشط، توليد حدث مختبري، العثور على الدليل، استيراده بمعرف ثابت، إعادة الاستيراد دون مضاعفة عدد الحالات، ثم عرضه مرتبطاً بمصدره. الدليل الاصطناعي وحده لا يثبت اكتمال الربط.

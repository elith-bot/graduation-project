# محرك القواعد ثم المحرك الهجين

وثيقة تصميم أولية. العتبات والأوزان والأطر الزمنية تضبط على بيانات التطوير وتثبت بإصدار قبل التقييم المستقل؛ لا توجد حالياً أرقام تشغيلية معتمدة.

## مراحل المعالجة وحدودها

1. integrations يحول حقول المصدر إلى عقد موحد؛ backend يتحقق ويحفظ الحدث ومعرف مصدره. لا نكرر normalizer خاصاً بـWazuh داخل engine.
2. backend يمنع إعادة إدخال المصدر نفسه تكراراً. engine يجمع التنبيهات المتكررة في قائمة العمل مع الاحتفاظ بالمعرفات والعدد والأوقات.
3. engine يربط أحداثاً حسب الحساب والجهاز والمصدر والزمن، ويطبق القواعد ويصدر أولوية مفسرة.
4. backend يحفظ القرارات وإصداراتها والأدلة؛ frontend يعرضها ويستقبل مراجعة المحلل.

لا نحذف أحداثاً مختلفة لأنها متشابهة، ولا ندمج حسابات أو أجهزة لمجرد اشتراكها بعنوان IP. حدود النافذة ومفاتيح الربط ومعاملة الأحداث المتأخرة جزء من العقود قبل التنفيذ.

## القواعد الخمس

| المعرف | الشرط المفاهيمي | الناتج | مثال موجب / سالب / بيانات ناقصة |
|---|---|---|---|
| R01 | فشل دخول متكرر للحساب ضمن نافذة معرفة | تجميع مع عدد المحاولات وتوقيتها | تكرار يتجاوز العتبة / محاولة واحدة / غياب الحساب يمنع ربطاً حسابياً مؤكداً |
| R02 | نجاح بعد فشل مرتبط في نافذة معرفة | حالة تتطلب سياقاً، لا حكم اختراق قطعي | فشل ثم نجاح مرتبط / نجاح بلا فشل سابق / غياب دليل النجاح لا يعني أنه لم يقع |
| R03 | جهاز أو مصدر غير معتاد بناء على تاريخ سابق موثوق | مؤشر يرفع الأولوية | مصدر جديد مقارنة بخط أساس / مصدر معتاد وحده لا يرفعها / بلا تاريخ: unknown وليس جديداً أو آمناً |
| R04 | مصدر يحاول على حسابات متعددة خلال نافذة معرفة | مؤشر احتمال Password Spraying | تعدد حسابات مع نمط متوافق / حساب واحد / غياب المصدر يمنع تأكيد النمط |
| R05 | نشاط حساس مرتبط بعد نجاح دخول | تصعيد للمراجعة مع الأدلة | تغيير صلاحيات مرتبط / حدث حساس غير مرتبط لا ينسب للجلسة / غياب هوية جلسة يوضح ضعف الربط |

تختبر كل قاعدة عند حدود العتبة والزمن، وعند نقص الحقول، وتعارض السياق، وإعادة الإرسال، ووصول الأحداث متأخرة. لا تستخدم حدثاً مستقبلياً عند حساب قرار تاريخي: حدث حساس يصل لاحقاً ينشئ نسخة قرار جديدة مع وقتها، ولا يضاف سراً لخصائص القرار السابق.

## القرار والتفسير

نحتفظ بنتيجة كل قاعدة والأدلة المتسببة وإصدار القاعدة والحقول غير المتاحة. الأولوية منفصلة عن نتيجة التحقيق. يمكن تقليل الأولوية بسياق موثوق، لكن المصدر المعروف وMFA الناجح لا ينفيان هجوماً وحدهما. يحدد اختبار المخاطر قواعد التصعيد التي لا يستطيع ML تخفيضها؛ لا نعتبر كل نتيجة R05 تلقائياً ضارة لأن نشاط الإدارة المشروع ممكن.

نحتاج تسجيل نسخة القرار، زمنه، التنبيهات المرتبطة، درجة القواعد وأسبابها، الأولوية، وحالة المراجعة. أوزان التجربة ليست احتمالاً أمنياً معايراً.

## التعلم الآلي لاحقاً

RandomForestClassifier مرشح أولي للبيانات الجدولية، وليس اختياراً مثبت الأفضل. الخصائص المرشحة: failed_attempts_5m وdistinct_accounts_5m ومعرفة الجهاز والمصدر وmfa_failures والنشاط الحساس المتاح وقت القرار والانحراف عن تاريخ الاستخدام وrule_score. كل خاصية لها تعريف زمني ومصدر ومؤشر فقدان؛ لا نحول unknown إلى false أو صفر يعني غياب الخطر.

وسوم benign/malicious تأتي من سيناريوهات وحقيقة مرجعية مستقلة، لا من rule_score أو حكم القواعد وحده. يبدأ النموذج بوضع Shadow Mode: يسجل توقعاته فقط ولا يؤثر على الأولوية. غياب النموذج أو فشله أو نقص الخصائص يرجع للمحرك القاعدي مع إظهار السبب.

لا نعتمد متوسطاً اعتباطياً مثل 50% قواعد و50% ML. بعد [التقييم](EVALUATION_PLAN.md) نحدد سياسة الدمج وحدود التصعيد والمراجعة. مخرجات predict_proba لا توصف تلقائياً كاحتمال موثوق قبل فحص المعايرة على بيانات مستقلة.

شفرة القواعد والقرار والخصائص والتنبؤ مكانها engine/؛ أدوات إنشاء مجموعات التقييم والمقارنة وتقاريرها مكانها evaluation/. مسار التدريب المرشح engine/ml/ يثبت عند بدء التنفيذ. التلخيص اللغوي اختياري ولا يحل محل الأدلة أو قواعد القرار.

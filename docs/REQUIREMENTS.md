# المتطلبات ومعايير القبول

هذه متطلبات مستهدفة؛ لم تنفذ بعد. تراجع مع [النطاق](PROJECT_SCOPE.md) و[القواعد](ENGINE_RULES.md).

| المعرف | المتطلب | معيار قبول قابل للاختبار |
|---|---|---|
| F01 | استقبال JSON موحد | يقبل عينة صالحة ويرفض غير الصالحة بسبب واضح دون إدخالها كمعلومة موثوقة |
| F02 | حفظ المصدر ومنع تكرار النقل | إعادة إرسال نفس هوية الحدث لا تنشئ نسخة جديدة؛ لا تضيع المحاولات المختلفة |
| F03 | تجميع وربط | السيناريو الموسوم ينتج مجموعات متوقعة، مع روابط لجميع الأدلة الأصلية |
| F04 | قواعد R01–R05 | لكل قاعدة حالات موجبة وسالبة وناقصة وحدود زمنية ونتائج مفسرة |
| F05 | أولوية وتفسير | يعرض الدرجة وأسبابها ونقص البيانات منفصلة عن الحكم النهائي |
| F06 | خط زمني | يعرض وقت الحدث ووقت الاستقبال ونسخة القرار دون استخدام المستقبل |
| F07 | واجهة المحلل | قائمة وتصفية وتفاصيل وحالات تحميل وخطأ وفراغ باستخدام API/JSON |
| F08 | مراجعة وتقرير | يسجل قرار المحلل وصاحبه ووقته؛ يربط التقرير بالأدلة والإصدار |
| F09 | تكامل Wazuh | حدث حقيقي من المختبر يصل للواجهة، مع اختبار تغطية المصادر وإعادة المحاولة |
| F10 | Shadow ML | يسجل توقعاً وإصدار نموذج دون تعديل قرار القواعد؛ يعالج تعذر التنبؤ بوضوح |
| F11 | تقييم مقارن | بيانات منفصلة وخط أساس ومقاييس قابلة لإعادة الحساب كما في خطة التقييم |

F01–F08 نطاق الأساس؛ F09 بوابة الربط الحقيقي؛ F10–F11 نطاق المقارنة البحثية عند توفر بيانات كافية. التلخيص اللغوي توسع اختياري مستقل.

## متطلبات الجودة

- الاحتفاظ بالأدلة وتتبع أصل القرار وقاعدة أو نموذج القرار وإعداداته.
- لا استجابة احتواء تلقائية، ولا افتراض سلامة بيانات مفقودة.
- توثيق مصدر كل حقل وسلوك الإدخال غير الصحيح والأحداث المتأخرة.
- صلاحيات API والتحقق من المدخلات وسياسة الاحتفاظ والنسخ الاحتياطي تحدد قبل عرض بيانات فعلية.
- تشغيل محلي أولاً، دون ادعاء جاهزية إنتاجية أو معالجة أحمال غير مقاسة.
- تحدد عتبات الأداء بعد قياس الجهاز والحمولة؛ ننشر المتوسط وp95 وبيئة القياس.
- لا بيانات شخصية أو أسرار في المستودع العام؛ بيانات المختبر المنشورة اصطناعية.

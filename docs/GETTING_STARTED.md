# نبدأ من أين؟

الحالة: توثيق وخطة فقط. لا يوجد بعد أمر يشغل تطبيق المنصة، فلا تستخدم uvicorn لمسار غير منشأ. لا تثبت اعتماديات عشوائية قبل أول مهمة تجهيز.

## أول جلسة للفريق (قبل البرمجة)

1. يقرأ الجميع [النطاق](PROJECT_SCOPE.md) و[التسلسل](SYSTEM_FLOW.md) و[دليل العمل](WORKFLOW.md).
2. نسجل الرام والمعالج والمساحة الحرة ودعم الافتراضية على الأجهزة؛ مساحة القرص التي قسناها قبل أيام لا تعتبر تحققاً حالياً.
3. نحدد مالك كل دور ومراجع بديل في [TEAM](TEAM.md)، والخبرة المتاحة بـPython ولينكس والشبكات.
4. نثبت مع المشرف أن التسليم الأول نسخة محدودة متكاملة، وأن ML وبقية الأفكار توسعات.
5. نختار مكان المختبر وصاحب صلاحية تشغيله، ونؤكد هل Wazuh جاهز فعلاً. المرجع [Wazuh](WAZUH.md).

## أول يومين من التنفيذ

- المهمة T01: اعتماد أول مخططات Alert وIncident وEvidenceAssessment وCoverageAssessment وعينات صالحة وناقصة وغير صالحة؛ لا نحتاج كل كيانات المستقبل دفعة واحدة.
- T02: تثبيت إصدار Python مدعوم ومتوفر لدى الجميع، pyproject أو requirements مقفل، بيئة معزولة، واختيار SQLite للنسخة المحلية وفق [القرار الهندسي](adr/0001-unified-platform.md).
- T03: تجهيز عينات السيناريو قبل ضبط الأوزان: نشاط سليم، نشاط ضار موسوم، ونفس التنبيهات مع مصدر لاحق غير متاح.
- T04: أول مسار صغير يعمل: JSON → FastAPI → قواعد بسيطة → حفظ → HTML/JavaScript. اختبار إعادة الإرسال وعدم تصنيف المفقود سليماً.

هذه المهام تنفيذية لاحقة وليست مكتملة بهذه الوثيقة. تفاصيل التسليم والتبعيات في [BACKLOG](BACKLOG.md).

## العمل بالتوازي

بعد اعتماد العقد، الواجهة تبدأ بعينات العقد، engine يعمل كدوال بلا قاعدة بيانات، backend يجهز التخزين وAPI، integrations يجمع حقول المصدر ويوثق التغطية، وevaluation ينشئ السيناريوهات والتوقعات المستقلة. لا ينتظر الجميع مختبر Wazuh ليكتبوا كل الشفرة.

## أول عرض نريد رؤيته

قائمة أقل من عدد التنبيهات الخام مع حسابات صحيحة، حادث يبين فشل دخول ثم نجاح، دليل لاحق ناقص، سبب النقص أو unknown، ونسخة قرار محدثة. في جزء التغطية نظهر مسارين ومكوّناً مشتركاً وتأثير فقدانه على سيناريو محدد. أي مدخل اصطناعي أو محاكاة موسوم بوضوح.

بعد هذا العرض نربط مختبراً حقيقياً ونختبر مسارات الكشف والتحسين. نقص المختبر لا يتحول إلى علامة إنجاز تكامل.

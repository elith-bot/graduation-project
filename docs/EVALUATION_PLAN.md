# خطة الاختبار والتقييم

الهدف: هل يقل عبء المحلل مع الحفاظ على كشف الهجمات؟ التجميع وحده لا يثبت تقليل False Positives.

بعد الدمج نقيس أيضاً: هل معرفة التغطية تقلل الإغلاق أو التخفيض الخاطئ عند فقد الأدلة؟ وهل توقع أثر الفشل والتحسين يطابق المختبر؟ لا نجمع كل ذلك في نسبة نجاح واحدة.

## تجربة النسخة الموحدة

- المسار A: فرز بالقواعد فقط، مقابل نفس القواعد مع checklist وحالة coverage. تثبت المدخلات والوسوم وتختلف معلومات التغطية المقصودة فقط؛ لا نمنح المسار الثاني معرفة مستقبلية أو حقيقة الوسم.
- المسار B: حالة Agent فقط، ثم عدد القواعد المهيأة، ثم خريطة تبعيات دون نتائج تحقق، ثم خريطة مدعومة باختبار. تقارن القدرة على توقع أثر فشل القناة والمكوّن المشترك، مع إعلان فرق المعلومات المتاحة لكل طريقة.
- قبل/بعد: نفس سيناريو الكشف وإعداداته الأخرى ونقطة نجاحه ونوع العطل، مع تحسين واحد موثق. تعاد التجربة أكثر من مرة وفق موارد المختبر مع توثيق التباين والمهلات والاستعادة.
- عند تعذر جمع المصدر أو تحضير المسار لا نسقط الحالات الصعبة من المقام بلا إعلان؛ نفرق unknown وnot_applicable والتغطية المحدودة.

## مقاييس الصمود والأدلة

| المقياس | كيف نحسبه؟ |
|---|---|
| خطأ الإغلاق/التخفيض عند نقص التغطية | الحالات الضارة التي أغلقت أو نزلت دون عتبة التحقيق / الحالات الضارة في المجموعة، مع العدد الخام |
| دقة توقع أثر الفشل | مقارنة predicted affected/unaffected بنتيجة المختبر لنفس السيناريو والمكوّن؛ unknown يظهر كتغطية تنبؤ منفصلة |
| صحة مجموعة الفشل | مقارنة الحلول بالبحث الشامل على أمثلة صغيرة ذات حقيقة مرجعية يدوية؛ إثبات أن كل مسار يتأثر وأن الحجم minimum ضمن نطاق البحث |
| تحسن الصمود | تغير المسارات المختبرة الناجية أو مجموعات الفشل ضمن نفس مجال الأعطال، لا زيادة عدد القواعد فقط |
| كلفة التحسين | زمن إعداد أو موارد مقاسة؛ لا رقم مالي افتراضي يدعى أنه مقاس |
| زمن الكشف | من نشاط اختبار معروف إلى نقطة النجاح المحددة، مع timeout وفصل غير المكتشف عن الزمن الناجح |

تظل مقاييس Precision/Recall للفرز في هذه الوثيقة؛ مصفوفة فشل المصادر لها معنى مختلف ولا تخلط بمصفوفة تهديد المستخدمين. لا ننسب كل نتيجة سلبية لفشل المنظومة: نثبت وقوع نشاط الاختبار أولاً وصحة شروط القاعدة وموعد وصوله.

سيناريو MVP للتحقيق مصادقة، وسيناريو الصمود رصد عملية محددة تدعم التحقيق بعد الدخول. اختبار مسارين لرصد عملية لا يثبت تغطية المصادقة نفسها. [البحث](RESEARCH.md) يحدد الأصالة غير المثبتة، و[الأمان](SECURITY.md) يحكم تنفيذ الأعطال.

## السيناريوهات والحقيقة المرجعية

مستخدم يخطئ بكلمة المرور، دخول شرعي من جهاز جديد، Brute Force، Password Spraying، نجاح بعد فشل، ونشاط حساس مشروع أو ضار بعد الدخول. تشمل حالات جهاز معروف مخترق، MFA غير متاح، بيانات متأخرة، حقول ناقصة، إعادة إرسال، ومصادر مختلفة تشترك بعنوان واحد.

لكل مجموعة معرف سيناريو وحسابات وأجهزة وأزمنة ووسم مستقل ونتيجة تجميع متوقعة. لا نستنتج الوسم من القواعد الجاري تقييمها؛ الحقائق في المحاكاة معروفة بتصميم السيناريو، والبيانات الواقعية تحتاج مراجعة موثقة. الغموض يوسم unknown ويعلن عدده؛ لا يحول خفية إلى benign.

## فصل البيانات ومنع التسرب

نفصل التدريب والتطوير والاختبار حسب سيناريو/جلسة أو زمن مع منع تداخل الأحداث المرتبطة، ونفحص تداخل المستخدمين والأجهزة حسب سؤال التجربة. لا تدخل نسخ من الحدث أو السيناريو نفسه بمجموعتين. بناء خط الأساس والخصائص والمعالجة المسبقة وضبط العتبات والمعايرة يعتمد التدريب/التطوير فقط. يثبت الاختبار ويستخدم بعد تثبيت الإعدادات. لا تستعمل أحداثاً لم تكن متاحة وقت القرار.

## المقارنات

1. خط أساس محدد بإعدادات Wazuh وقواعده ومستوى العرض ونسخته، أو خط أساس واضح على نفس المدخلات عند عدم توفر المختبر.
2. محرك القواعد وحده.
3. المحرك الهجين بعد انتهاء Shadow Mode وإقرار سياسة تأثير النموذج.

توقعات Shadow وحدها لا تمثل نظام Hybrid منشوراً. نقارن على نفس السيناريوهات والوسوم وبوحدة قرار متوافقة. عند اختلاف مصادر البيانات نعلن الفرق ونفصل أثر الإثراء عن أثر ML، ولا ننسب التحسن كله للنموذج.

## المقاييس

| المقياس | التعريف |
|---|---|
| Precision | TP / (TP + FP) وفق عتبة تعريف التهديد المثبتة |
| Recall | TP / (TP + FN) للهجمات أو الحوادث الضارة، لا لعدد التنبيهات الخام |
| False Positive Rate | FP / (FP + TN) من الحالات السليمة |
| تقليل قائمة العمل | 1 − عدد الحالات التي تتطلب مراجعة / عدد وحدات خط الأساس المناظرة في الفترة نفسها |
| عبء المحلل | عدد حالات المراجعة؛ والوقت لا يدعى تحسنه إلا بتجربة بشرية أو قياس موثق |
| أخطاء التخفيض | عدد ونسبة الهجمات التي خفضت إلى مستوى دون عتبة المراجعة، مع أسبابها |
| الأداء | متوسط زمن المعالجة وp95 وحجم البيانات ومواصفات الجهاز |

نثبت ما هو Positive: مثلاً الحالة التي يضعها النظام بقائمة التحقيق العاجل/المراجعة وفق السياسة. حالة ضارة منخفضة الأولوية تحسب FN لهذا القرار حتى لو بقيت قابلة للبحث. نبلغ تغطية الوسوم والحالات غير المحسومة والمراجعة البشرية، والمقاييس عند المقامات الصفرية تكون غير متاحة لا صفراً مصطنعاً.

نميز ثلاثة أعداد: التنبيهات الخام، الحوادث بعد التجميع، وحالات المراجعة. دمج 20 تنبيهاً بحادث واحد لا يعني 19 إنذاراً خاطئاً. لا تكفي Accuracy مع عدم توازن البيانات. ننشر مصفوفة الالتباس وأعداد العينات وبذور العشوائية وإصدارات البيانات والقواعد والنموذج؛ ومع الإمكان تقدير عدم اليقين على مستوى السيناريوهات.

## أهداف بحثية لا نتائج

تقليل عبء المراجعة 50% وRecall بنسبة 95% مثالان لأهداف مبدئية تحتاج موافقة المشرف وبيانات كافية. لا ضمان لتحقيقهما، ولا إثبات بتجربة صغيرة منتقاة. نعرض منحنى المفاضلة بين تقليل المراجعة وفقد الهجمات ونقبل أن ML قد لا يحسن خط الأساس.

## بوابة تفعيل ML

بيانات موسومة مستقلة كافية، تحسن قابل للتكرار على الاختبار وفق معيار متفق عليه، عدم تجاوز حد فقد الهجمات، توثيق المعايرة إن وصفت المخرجات باحتمالات، وتوفر الرجوع للقواعد. إن لم تتحقق الشروط يبقى ML في Shadow Mode وتعرض النتيجة البحثية كما هي.

التنفيذ والعينات والتقارير داخل evaluation/؛ اختبارات الوحدات بجوار كود كل مكون. حالة جميع المقاييس حالياً: لم تقس.

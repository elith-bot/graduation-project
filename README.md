# SOC Investigation & Detection Resilience Platform

مشروع تخرج قسم هندسة الأمن السيبراني: منصة التحقيق الأمني وفرز الحوادث وتقييم صمود الكشف. الاسم وصفي للعمل، والعنوان الأكاديمي النهائي يثبت مع المشرف. يحتفظ المشروع بمساعد SOC الأصلي ويضيف وحدة SHIELD-X محدودة لتقييم التغطية والتبعيات.

يستقبل التنبيهات الأمنية، ويجمع المتكرر منها، ويربط الأحداث بحوادث، ثم يرتب الأولويات ويعرض الأدلة وخطوات التحقيق المقترحة. Wazuh مصدر للتنبيهات؛ مساهمة الفريق هي محرك الربط والفرز والتفسير والتقييم. الاستجابة في النسخة الأولى توصيات يراجعها المحلل.

## الفكرة الموحدة والتسلسل

**استقبال → تجميع وفرز أولي → فحص الأدلة الناقصة → التحقق من التغطية والمصادر → تحديث التحقيق → اقتراح تحسين → اختبار قبل وبعد.**

المرحلة الأولى تقلل التكرار وزحمة قائمة العمل، ولا تحكم بأن كل ما أخفته عن القائمة تنبيه خاطئ. حالة المصدر والتغطية ترجع لتصحح قرار الفرز: غياب تنبيه أثناء فقدان المراقبة لا يثبت السلامة. الأولوية ونتيجة التحقيق وصحة التغطية ثلاثة أشياء منفصلة.

نبدأ بقواعد مفسرة وسيناريو تحقيق واحد، وسيناريو كشف محدود بمسارين مختبرين ومكوّن مشترك وتحسين واحد. ML بنمط Shadow، والتلخيص اللغوي، وترتيب الفحوص المتقدم، وSilent Risk Debt توسعات لاحقة؛ لا تجمع كلها ضمن وعد الشهرين.

## المرجع المعتمد للفريق

الهيكلية في [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) هي المرجع المعتمد لحدود الأجزاء والتقنيات. أي تغيير عليها يمر بطلب دمج ومراجعة الأعضاء المتأثرين.

| المجلد | المسؤولية | التقنية |
|---|---|---|
| backend/ | استقبال البيانات والتخزين وواجهة API | Python + FastAPI |
| engine/ | الفرز والأدلة وصمود الكشف والقرار المفسر | Python |
| frontend/ | واجهة المحلل والحوادث والتقارير | HTML + CSS + JavaScript |
| integrations/ | ربط Wazuh وتحويل بياناته | Python + إعدادات Wazuh |
| evaluation/ | السيناريوهات وبيانات الاختبار وقياس النتائج | Python |
| contracts/ | عقود البيانات المشتركة | مواصفات موثقة، ثم مخططات قابلة للتحقق |
| docs/ | البحث والتوثيق والقرارات | Markdown |
